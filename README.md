# 新廊华小校内竞赛管理系统 · v7

前端为静态网页，后端为 Google Apps Script + Google Sheets。

- `index.html`：现有三语界面、排名、打印、Excel 和海报。
- `app-sync.js`：登录、年度快照、持久化补传、断网恢复、冲突处理。
- `app-actions.js`：报名、评分和比赛管理。
- `Code.gs`：权限、业务校验、年度数据、版本检查、操作日志及迁移。

## 先阅读：本次升级不会自动部署 Apps Script

前后端必须配套升级。不要仅合并网页而继续使用旧后端。
旧接口存在未授权写入问题；新部署验证完成后，必须停用旧 Web App 部署，不能仅隐藏旧链接。
详见 [部署与回退步骤](DEPLOYMENT.md)。

## 权限与行为

| 身份 | 可执行操作 |
| --- | --- |
| 未登录 | 查看比赛信息；不返回学生名册、成绩 |
| 教师共享凭证 | 查看学生资料、报名、录入成绩和备注 |
| 管理员共享凭证 | 教师权限，加删除报名和比赛管理 |

密码保存在脚本属性中；浏览器只在当前会话内存中保留密码，不写入 localStorage。
角色凭证是兼容现有系统的过渡方案，**不是教师个人账户**；服务器日志中的 `actor` 只表示角色。

写入在联网前先保存补传队列。队列按先后顺序发送，连续评分最多每次 20 条。
每条操作有唯一 ID；服务器使用持久化操作日志恢复中断、重放成功凭证。
批量请求按条提交，遇到首个错误停止，之前成功的条目不会撤销。
版本不一致时暂停补传，不强行覆盖；用户可以导出备份、移除明确失败的操作，再查看云端值重新录入。
同一记录有待上传操作时禁止继续叠加修改。

## 数据结构

升级后使用 `Competitions_v7`、`Students_v7`、`Results_v7`、`Operations_v7`。
比赛、学生和报名使用稳定 ID；所有业务记录包含年度。年度学生名册独立维护，跨年度同一学生暂不自动关联。
比赛重命名依靠 ID 关联，不逐行改写报名。删除采用软删除，记录及操作历史保留。
不要直接修改 v7 表的 ID、version、deleted、lastOperationId、操作日志或表头。
手工修改数据会绕过版本和审计保护；应使用应用界面。

## 测试

需要 Node.js 20 或更新版本，无需安装第三方包：

```sh
npm test
```

测试使用内存中的 Apps Script 服务模拟，不接触生产表。
覆盖权限、年度隔离、零分、备注、去重、版本冲突、日志恢复、迁移、队列持久化和错误保留。
GitHub Actions 对 push 和 pull request 运行同一套测试。

可选浏览器冒烟测试需要 Playwright 和 Microsoft Edge：

```sh
node tests/browser-smoke.cjs
```

浏览器测试拦截所有网络请求，使用模拟接口和学生数据，不访问真实后端。
它验证界面交互和 HTML 注入防护，不验证 CDN 字体样式、Excel 文件质量或真实 Google 授权与配额。

## 仍需了解的边界

- 页面资源仍使用现有 CDN；没有新增 Service Worker，无法保证断网后首次打开页面可用。已经打开的登录会话可保留待上传工作。
- 浏览器缓存及待上传资料包含学生信息。共享设备使用后请退出；待上传操作为了防丢不会随退出删除，应先处理完毕。浏览器配置文件的使用者仍可读取本机存储。
- Google Sheets 不是事务数据库。写入日志加锁可恢复应用请求中断，但无法协调人工表格编辑或其他不使用同一脚本锁的程序。
- 操作日志保留修改前后值，不自动清理；规模增长后需制定归档策略并评估迁移数据库。
- 自动排名保留现有并列规则（1、1、3）及按年级/公开组设置。
- 同名团队在新报名中有独立 teamId；旧数据迁移保留原来的“比赛＋队名”分组，迁移前需核对同名团队是否实际属于不同队伍。
- 教师个人账户、成绩发布审批和完整离线安装作为后续升级，不在本次交付中。
